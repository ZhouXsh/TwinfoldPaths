# 《双生折线》设计思路

> **参赛评审版｜重点对应：玩法设计 · 关卡体验 · AI 驾驭力 · 迭代打磨**
>
> 《双生折线》（Twinfold Paths）是一款手机竖屏、可离线运行的双角色空间解谜游戏。它没有复杂操作：玩家始终只输入 **上、下、左、右** 四个方向；真正的难点来自——**同一条指令会同时作用于两个角色，却产生不同的结果。**

# 1. 核心命题：用最少的输入，制造最多的因果判断

多数移动解谜的基本问题是：“**我往哪里走？**”

《双生折线》把问题改成：“**如果我输入这个方向，两个人分别会发生什么？下一回合我还能不能把他们重新对齐？**”

玩家每次只做一个动作，但要同时预测两个角色的后果：

- 蓝色角色：执行玩家输入方向；
- 橙色角色：默认执行水平镜像方向——左 ↔ 右，上 / 下保持一致；
- 某一角色被墙、边界或机关阻挡时，它原地停留，另一角色仍然可以移动；
- 若回合结算后两名角色落在同一格，则整条指令取消；
- 若两名角色相邻并互换位置，则允许**对穿交换**；
- 只有回合结束时，两名角色分别同时站在自己的出口，才算胜利；先到出口的角色不会被“锁住”。

这组规则刻意保持输入极简，却形成了三个层次的推理张力：

**第一层：同令异动。** 一个方向同时改变两个角色，玩家不能只盯着“主角”。

**第二层：受阻解耦。** 墙不是单纯的障碍，而是玩家主动利用的“同步破坏器”。把一名角色卡住，往往正是让另一名角色获得自由位移的办法。

**第三层：相遇再耦合。** 两名角色最终又必须在同一套空间中重新协调。对穿、错位、会车、共享走廊，让“两个角色之间的关系”比单个角色的路线更重要。

因此，本作的核心乐趣并不是找一条路，而是**操纵一对相互耦合、又可被环境暂时解耦的运动系统**。

# 2. 为什么规则要这样设计

## 2.1 不增加操作复杂度，而增加“思考密度”

移动端 H5 的输入应该足够轻：单手滑动、方向键都能完成全部操作。我们没有通过更多按钮制造复杂度，而是让每个按钮背后的状态变化更丰富。

一个“←”可能意味着：蓝左移、橙右移；也可能蓝被墙挡住而橙右移；还可能两者互换；也可能因为最终同格而整回合取消。**操作词汇只有四个，结果词汇却远多于四个。**

这让游戏很适合短时游玩，又保留了真正的推理空间。

## 2.2 失败成本低，难度来自推理而不是惩罚

本作不设倒计时，首次通关不限制步数，并提供无限撤销与快速重开。目标步数只用于星级和优化挑战。

这是一个刻意的产品选择：如果玩家正在学习“双角色因果关系”，高额失败成本只会迫使玩家保守试探；而低成本撤销可以鼓励玩家验证假设、形成空间模型。我们希望玩家的心理循环是：

**预测 → 尝试 → 观察双角色结果 → 修正模型 → 再预测**，而不是“操作失误 → 被惩罚 → 重复劳动”。

## 2.3 墙体从“限制”变成“工具”

在普通迷宫里，墙的功能是“不让你过去”；在《双生折线》中，墙还承担一个更重要的功能：**让两个角色暂时失去同步。**

例如同一条“↑”指令，如果蓝色前方有墙而橙色没有，结果就是蓝停、橙走。这个看似简单的差异，是大量中后期谜题的基本语法。玩家逐渐从“避开墙”转变为“寻找能让我只移动其中一人的墙”。

这种认知反转，是我们认为最能代表《双生折线》的设计特征之一。

# 3. 机制不是堆叠，而是给核心规则增加新的“句法”

我们在基础规则上逐步加入 M1～M9，但原则始终是：**新机制必须改变玩家如何利用双角色关系，而不是只增加一个新图标。**

| 机制 | 表面功能 | 真正服务的解谜能力 |
|---|---|---|
| **M1 压板 / 门** | 站上压板开启门 | 用一名角色的位置为另一名角色创造通路，强化“彼此开路” |
| **M2 角色专属门** | 只允许指定角色通过 | 让同一空间产生非对称可达性 |
| **M3 暂停格 / 暂停令牌** | 下一次输入让一名角色停留 | 玩家主动制造“一停一走”，把受阻解耦从地形扩展为状态资源 |
| **M4 映射切换器** | 改变橙色角色的方向映射 | 改写“同一输入如何作用于两人”，直接改变核心控制关系 |
| **M5 单向格** | 限制离开方向 | 把位置与下一步选择绑定，制造方向性的错位窗口 |
| **M6 传送门** | 改变空间位置 | 瞬间打破局部相对位置，让两条轨迹重新交织 |
| **M7 脆弱格** | 离开后坍塌 | 把路径选择变成不可逆的空间承诺 |
| **M8 同步脉冲** | 同一回合完成双点触发 | 直接考察两名角色的同步时机 |
| **M9 奇偶相位门** | 门随回合奇偶切换 | 在空间关系上再加入“时间相位”，让何时到达与如何到达同等重要 |

除此之外，第二阶段又引入了**探索视野**。它与 M1～M9 的定位不同：迷雾不改变角色能不能走、机关怎么结算、BFS 最短解是什么，而是改变玩家**知道多少**。

这使我们获得了一个独立于谜题逻辑的难度轴：同一张地图、同一套最优解，可以只通过信息量调整为不同体验，而不需要复制三套关卡。

# 4. 最终三档难度：调整“信息预算”，而不是偷偷改谜题

为了让探索机制既能形成特色，又不把所有玩家都强迫进同一种信息压力，最终版本把视野抽象为三档难度：

| 难度 | 信息规则 | 体验定位 |
|---|---|---|
| **简单** | 全地图常亮，无迷雾 | 纯空间规划，适合第一次理解机关或只想解题的玩家 |
| **标准（默认）** | 当前两球附近九宫格可见；探索过的区域**完全点亮并永久保留** | 兼顾探索与规划，逐步建立整图认知 |
| **困难** | 只显示当前附近九宫格；离开后的区域重新被迷雾覆盖 | 强调短期记忆、方向感与风险判断 |

这里最重要的工程与设计边界是：**难度只改变表现层可见性，不修改正式关卡的几何、机关、胜利条件、`parMoves` 或 BFS 语义。**

因此，三个难度不是“简单版关卡 / 困难版关卡”，而是**同一个谜题的三个信息窗口**。这种设计保证了关卡设计本身仍然只有一个事实来源，也让成绩、最优解与可解性保持一致。

# 5. 五章不是 50 个编号，而是一条认知曲线

第一阶段已经规划了 5 章 50 关，但第二阶段最重要的工作之一，是把“章节有名字”进一步打磨成“章节真的有不同思考方式”。最终内容曲线可以概括为：

| 章节 | 核心认知任务 | 关卡体验 |
|---|---|---|
| **第一章 1–10：读懂双生** | 理解镜像、单侧受阻、同时抵达 | 紧凑地图、短解、低试错成本；最短步数形成 `1→3→4→6→6→6→6→7→6→9` 的教学—练习—章末挑战节奏 |
| **第二章 11–20：进入共享空间** | 学会错位、会车、对穿 | 从第 11 关明确提示“难度飙升”；后续关卡不再把两球隔离在两条独立路线中 |
| **第三章 21–30：扩大决策半径** | 在更大开放迷宫中组合机关 | 岔路、回环、死胡同增多，必须同时规划两个角色的未来位置 |
| **第四章 31–40：暗域探索** | 在信息不完整时建立空间记忆 | 探索视野成为章节身份；设计过程中还验证过无痕、衰减、雷达、信标等探索变体，最终由统一难度系统承接信息压力 |
| **第五章 41–50：空间 + 时间合流** | 把共享迷宫、双角色互锁与时相状态综合起来 | 大地图与 M8/M9 等时间约束叠加，要求同时处理位置、顺序与回合节拍 |

后 40 关最终重制后，BFS 平均最优步数也呈现明确的章节递进：第二章 **16.7**、第三章 **19.5**、第四章 **20.7**、第五章 **23.8**。这不是把“步数越长”直接当作“人类越难”，而是用它检查内容规模是否真的随章节增长；真正的认知难度仍结合机制引入、信息量、岔路与双球耦合程度判断。

# 6. 最大的一次设计推翻：从“双通道”到“开放共享迷宫”

第二阶段曾经出现一个很典型的“AI 作品看起来变好了，但本质没有变”的问题。

最初我们扩大了地图、加入迷雾、增加支路，甚至让蓝橙两侧通过压板门互相影响。视觉上已经比第一版复杂很多，但进一步试玩与审视后发现：**许多地图的底层几何仍然来自“蓝线 + 橙线”两条预设路线。** 玩家虽然看到更多墙，却仍然是在沿固定通道推进。

如果到这里就停止，评审看到的会是“地图越来越大”，玩家感受到的却仍是“换汤不换药”。因此我们直接否定了这批后期关卡，重新定义验收标准：

**不是检查 JSON 是否不同，而是检查玩家在最优解里是否真的发生了我们想要的行为。**

于是 level-011～050 共 40 关被再次全部重制为开放共享迷宫，并对地图图结构与 BFS 回放同时做审计。最终得到：

- **40 / 40**：最优解真实发生蓝橙相邻格对穿交换；
- **33 / 40**：如果禁止对穿，会变为不可解、搜索超预算或最短解变长——说明对穿不是装饰动作，而具有实际解题价值；
- **40 / 40**：两名角色的最优路径存在至少 2 个共享访问格，避免两条互不相关的专属路线；
- **37 / 40**：最优解同时出现“蓝停橙走”和“橙停蓝走”两种单侧受阻，证明关卡真正利用了双向解耦；
- 后 30 关平均最优步数由中间版本的 **18.90** 进一步提升到 **21.33**；
- 地图最终扩展到约 **7×7～11×11**，同时要求分岔、死胡同与图环路，而不是用更大的空白区域虚增尺寸。

这轮重制确立了一个最终设计原则：

> **《双生折线》的关卡价值，不在于“迷宫长什么样”，而在于它是否迫使玩家利用“双生关系”。**

# 7. 我们如何让 50 关避免“AI 批量生成感”

AI 很适合批量生成候选，却不天然擅长判断“连续十关玩起来是否像同一关”。因此从第一阶段开始，我们就没有把第一批 AI 输出直接当正式关卡，而是建立了从生成到淘汰的工具链；第二阶段又继续强化这套“机器生成、机器审计、人工定标准”的方法。

最终一关进入正式内容前，至少要经过以下几类检查：

1. **结构合法性**：JSON Schema、坐标、实体引用、传送配对、机关连接均合法；
2. **规则可解性**：BFS 必须可解，并能够把最短解逐回合回放到胜利；
3. **最优步数真实性**：`parMoves` 不由人或 AI 猜测，严格来自 BFS，测试要求 `parMoves === optimalSteps`；
4. **解法差异性**：比较最短解的 exact、Levenshtein、2-gram / 3-gram 模式，避免不同地图执行同一套“手势节奏”；
5. **机制有效性**：不能只把机关摆在地图上，最优解应真实触发本关宣称的机制；
6. **图结构质量**：开放度、分岔、死胡同、环秩等指标保证地图不是细管；
7. **双球行为质量**：统计对穿、共享访问、单侧受阻等回放事件，确认谜题确实围绕核心玩法；
8. **表现回归**：移动端 E2E 检查棋盘、HUD、按钮、提示与不同视口下的可用性。

这里最能体现 AI 驾驭力的一点是：**我们没有要求 AI “更有创意一点”，而是不断修改 AI 的评价函数。** 当“地图不同”仍然不好玩时，就增加解序列相似度；当“地图更大”仍像管道时，就增加图结构门槛；当“共享迷宫”仍不足以证明双球互动时，就直接审计 BFS 行为轨迹。

主观设计目标被逐层翻译为可计算证据，AI 才从“内容生成器”变成真正可控的设计执行工具。

# 8. 关卡之外的体验：让玩家读得懂自己的失败

解谜游戏最怕的不是“难”，而是“我不知道为什么不行”。因此 UI 与反馈的目标不是装饰，而是**缩短玩家从结果回溯原因的时间**。

我们针对这一点做了几类设计：

- 首页提供完整教学入口，集中解释双角色映射、单侧受阻、同格取消、对穿以及主要机关；
- 前期关卡使用更具体的行为提示，而不是只写抽象规则；
- HUD 提供显式 `?` 提示按钮，提示只指出关注点，不强制展示完整答案；
- 受阻、传送、机关触发、单角色先到出口等状态提供即时反馈；
- 第 11 关进入开放共享迷宫阶段时明确提示“难度飙升”，给玩家一次认知预期切换；
- 所有关键触控目标按移动端设计，棋盘根据可用空间动态缩放；
- 角色与机关不仅依赖颜色，还结合形状、纹理和符号表达。

第二阶段还专门修复了通关页纵向重叠、窄屏布局、选关信息层级等问题。**这些修改不增加规则深度，却决定玩家是否愿意继续理解规则深度。**

# 9. 技术架构为什么也是玩法设计的一部分

我们从一开始就把“游戏规则”和“画面表现”分开：核心回合引擎是纯 TypeScript，Phaser 只负责把结果画出来。BFS 求解器复用同一套领域规则，而不是自己写一套“近似规则”。

这看起来是工程选择，实际上直接保护了关卡设计：

- 动画不能偷偷改变逻辑，因此视觉效果和真实状态一致；
- 撤销恢复完整状态，玩家可以放心实验；
- 求解器与游戏共享规则，AI 不能生成一张“求解器说可解、实际游戏却不可解”的假关卡；
- 新增 M9 时，回合奇偶进入稳定哈希，搜索器才不会把不同相位的状态错误合并；
- 探索难度只覆盖可见性视图，不污染原始正式关卡，因此三档难度不会产生三套互相漂移的数据。

最终发布仍保持**无后端、无账号、无 CDN、单文件离线 H5**。复杂度尽量留在玩法本身，而不是部署环境。

# 10. 我们认为《双生折线》真正的差异化是什么

如果只列功能，《双生折线》有镜像、门、传送、脆弱格、迷雾、相位门……但这些都不是最重要的答案。

真正的差异化是四件事彼此咬合：

**其一，一次输入驱动两个不同结果。** 玩家始终在处理“关系”，而不是轮流操作两个角色。

**其二，障碍可以成为控制工具。** 墙和门不是单纯阻止前进，而是帮助玩家选择性地让某一角色停止。

**其三，对穿是主动资源。** 两个角色并非只需要互不碰撞；它们要在共享空间中相遇、交换、错位，再重新同步。

**其四，信息量本身也是难度。** 最终三档模式在不改谜题真值的情况下，让完全可见、永久探索记忆和无记忆迷雾形成三种体验。

因此，整个游戏可以被一句话概括：

> **“你只能下达一条命令，却要同时安排两条命运。”**

# 11. 证据与真实性说明

本项目明确区分**真人试玩、AI 认知走查、BFS / 自动化数据**。截至当前仓库记录，没有把 AI 走查伪装成真人试玩，也没有虚构玩家人数、完成率或评价。我们对关卡体验的量化证据来自领域求解、最短解回放、图结构审计、自动化测试和实际开发过程中的人工反馈；真人体验结论只在有真实数据时才会声明。

这也是整个项目的 AI 使用原则：**AI 可以生成方案、代码、关卡和分析，但“什么值得留下”必须由明确的设计目标、可复核证据和人工判断共同决定。**
