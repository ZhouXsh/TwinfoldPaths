# ADR-010：状态管理（无框架，快照撤销）

- 日期：2026-08-22
- 状态：accepted
- 影响需求：FR-03/05/07、R-06、I3/I4/I8
- 影响阶段：03、05、06、12

## 背景

需要确定运行时状态的所有权与变更方式：是否引入状态管理库（zustand/redux 等），撤销如何实现，表现层如何感知变化。

## 候选方案

1. 无框架：`GameState` 为唯一事实，`resolveTurn/undo/restart` 为纯函数；撤销=Snapshot 栈（`docs/domain-model.md` §7）；表现层每回合后主动拉取/订阅事件。
2. 引入轻量状态库（zustand）：组件式订阅。
3. 命令模式记录输入序列，撤销=重放。

## 决策

方案 1。

## 理由与证据

状态结构已在阶段 02 完整定义且可序列化（I8），Snapshot 栈实现约 30 行、语义与"恢复全部动态状态"逐字段对应（I4）；方案 2 为 UI 状态库，对确定性游戏逻辑无增益且新增依赖；方案 3 重放含随机性风险且撤销成本随回合数增长，违反无限撤销的即时性预期。

## 后果

`src/domain` 提供 `resolveTurn`、`undo`、`restart`、`projectSnapshot` 纯函数；Game 场景持有唯一 `GameState` 实例；事件仅用于触发渲染刷新，不携带状态副本。

## 复查条件

若 history 内存占用在长会话中被实测证实过大（阶段 12/13），评估结构共享优化（不改对外语义）。
