# ADR-014：MVP 表现层 UI 形态与动画期输入策略

- 日期：2026-08-23
- 状态：accepted
- 影响需求：FR-01/02/04/05、NFR-02/04
- 影响阶段：06、11

## 背景

阶段 06 需要 HUD（关卡名、步数、撤销、重开）、四向按钮与结算按钮。有两个待定项：UI 用 Phaser 画布内对象还是 DOM；动画期间输入是丢弃（锁）还是排队。Phaser 3.90 的 ScaleManager（FIT 模式）不监听父容器尺寸变化（无 ResizeObserver，仅 500ms 轮询且实测父容器缩小时画布不收缩、只重新居中），场景切换导致的 DOM 布局变化会使画布溢出并遮挡按钮（WebKit 实测命中测试失败）。

## 候选方案

1. 全画布 UI：按钮/文本均为 Phaser 交互对象；E2E 需按坐标点击画布，触控目标与无障碍成本高。
2. DOM 覆盖层 UI：HUD/方向键/结算按钮为 DOM（data-testid），棋盘与角色动画留在 Phaser 画布；布局条栏始终占位、仅切换可见性，保证 Phaser 父容器尺寸稳定。
3. 动画期排队一条输入：实现更复杂，撤销/重开与队列交互语义多，MVP 阶段收益低。

## 决策

方案 2 + 动画期锁输入（丢弃而非排队）。

## 理由与证据

- DOM 按钮天然满足 NFR-04（≥44px 触控目标）、E2E 稳定定位（data-testid）与可访问性（aria-label），符合 MVP 最小成本。
- 布局条栏（HUD/控制条）用 `visibility` 切换保持占位，`#stage` 尺寸在所有场景恒定，实测画布 506×506 精确贴合且三引擎两连跑无遮挡（`artifacts/stage-06/`）。
- 锁输入语义简单可测：`src/input/gate.ts` 单测覆盖；E2E 以 `SETTLE_MS` 等待动画结算，终态步数精确断言。

## 后果

- `src/scenes/dom-ui.ts` 管理条栏显隐与 HUD 文本；场景只读领域状态、经 `MoveResult` 驱动动画（ADR-008 不变）。
- 阶段 11 完整 UI 可沿用 DOM 形态；若改为画布内 UI，须先解决 Phaser 父容器缩放问题。
- 已知限制：动画 180ms 内的方向输入被丢弃（撤销/重开不受限，随时可用）。

## 复查条件

阶段 11/13 若实测玩家对"丢输入"反馈强烈，评估单条排队；若引入章节/关卡选择页导致布局再次动态变化，须保持 Phaser 父容器尺寸稳定或改 RESIZE 模式。
