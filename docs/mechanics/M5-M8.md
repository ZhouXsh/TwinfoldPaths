# 机制手册 M5–M8（阶段 08）

> 面向后续阶段（09 工具链、10 关卡生产）的机制事实说明。规则唯一事实来源仍是 `docs/turn-resolution.md` 与 `docs/decision-log.md`；本文件汇总 M5–M8 的语义、表现编码、关卡清单与测试地图。M1–M4 见 `docs/mechanics/M1-M4.md`。

## M5 单向格

- 无状态字段（纯静态约束，P4 第 6 条）。
- 进入不受箭头限制（任意方向、移动或传送落点均可进入）；离开时方向必须等于 `arrow`，否则该角色停留（`blocked=true`、`reason='oneWay'`）。
- 阻挡优先级：目标格阻挡（边界/墙与坍塌/门）先于离开约束——目标格是墙时 `reason='wall'`（P4 顺序）。
- **阻挡反馈与墙不同但逻辑确定**：`MoveResult.blue/orange.reason: BlockReason | null`（`bounds|wall|door|colorDoor|pulseDoor|oneWay|pause`）由引擎输出；表现层对 `oneWay` 用原地左右抖动 + 状态行"单向格只能顺箭头离开"，对墙/边界用方向性冲撞。坍塌脆弱格的阻挡原因记为 `wall`。
- 映射交互：判定使用**映射后**的有效方向（橙色在 V_MIRROR/ROTATE_CW 下输入方向≠实际方向）。
- 关卡：教学 `level-031`（顺箭而行，par 7）；组合 `level-034`（M4+M5 映射与离向，par 5）、`level-038`（M5+M6 传送接单向，par 3）、`level-044`（M5+M7 不可回头路，par 6）。

## M6 传送门

- 无状态字段（纯静态实体 + 每回合末一次性结算；"每回合至多一次"由结算结构保证，无隐藏冷却状态，不占序列化）。
- 成对：同 `portalId` 的 `end: 'A'/'B'`；`target` = 另一端坐标。
- 触发：回合末（D2，先于 D1/D3/D4/D5/D6）对"移动阶段结束后站在入口格上"的角色结算。被阻挡停留、被暂停停留在入口上同样触发。
- 失败判定（基于**传送阶段开始时**的位置，即移动后位置；ADR-006）：
  - a. 目标出界/墙/坍塌脆弱格/关闭普通门/不匹配专属门/未激活脉冲门 → 失败停留；
  - b. 目标 == 另一角色当前位置且其不传送 → 失败停留；
  - c. 双方互传 → 同时交换（成功）；
  - d. 双方目标同格 → 双双失败；
  - e. 目标被占据者同回合走开 → 成功。
- **每角色每回合最多传送一次（I5）**：`teleportActors` 单次调用、无循环重入；落点是另一入口格不再二次传送。传送链每回合只前进一跳（测试以三入口链锁定）。
- 落点参与后续动态结算：可压板（D4）、站切换器（D3）、触发脉冲配对（D5）、获得暂停令牌（D6 视为新抵达）、离开脆弱格触发坍塌（D1）。
- 已知引擎事实：**同格存在多个传送入口时按 `entities` 数组顺序取第一个**（确定性 I3）；阶段 09 校验器应禁止入口重叠与 portal 不成对。
- 表现：传送瞬间改位 + 淡入（无补间飞行），状态行"蓝/橙被传送"。
- 关卡：教学 `level-036`（穿墙之门，par 3）；组合 `level-038`（M5+M6，par 3）。

## M7 脆弱格

- 状态字段：`GameState.fragileCollapsed: Point[]`（初始为空；进入快照、哈希、序列化、撤销）。
- 坍塌时机（D1，读 D2 后位置）：回合开始站在脆弱格、最终位置离开该格（移动或传送）、该格未坍塌、且 **D2 后该格无任一角色占据**（ADR-016）→ 记入坍塌集合。被阻挡/暂停停留不坍塌；进入与停留不坍塌（I12）。
- 坍塌后等同墙体：阻挡任何角色进入（P4 第 2 条，`reason='wall'`）。
- 撤销/重开/存档完整恢复（I4、I16、I8）。
- 表现：完整 = 暖底色裂纹贴图 `fragile`；坍塌 = 暗坑碎屑 `fragile-collapsed`；坍塌回合状态行"脆弱格坍塌"。精灵状态由 `syncEntityStates` 从 `GameState` 驱动。
- 关卡：教学 `level-041`（脆弱之桥，par 5）；组合 `level-044`（M5+M7，par 6）。

## M8 同步脉冲

- 状态字段：`GameState.pulseDoors: Record<pairId, boolean>`（初始全关，由 `pulseDoor` 实体注册；快照/哈希/序列化/撤销全覆盖）。
- 触发（D5，读 D2 后位置，**占用语义**）：回合末某 `pairId` 的两个 `pulseSwitch` 各被一名角色占用（无论本回合抵达还是此前驻留）→ `pulseDoors[pairId]=true`。
  - 同回合双双抵达 → 闩锁；一方驻留（被阻挡/暂停）另一方抵达 → 同样闩锁；
  - 错回合（从未同时占用）→ 永不闩锁；单方占用无效。
- 闩锁只置真不回退（I17）：离开开关不关闭；仅撤销可还原；还原后可再次触发。
- `pulseDoor`：未激活阻挡（P4 第 5 条，`reason='pulseDoor'`，状态行"脉冲门未激活"）；激活后永久可通行。同 `pairId` 的多个 `pulseDoor` 共享一个闩锁。
- 表现：开关 = 圆形按钮贴图（被占用时高亮）；门 = 品红栅栏（关）/沉底边框（开）；闩锁回合状态行"同步脉冲达成，脉冲门开启"。
- 关卡：教学 `level-046`（同步脉冲，par 6）；组合 `level-047`（M3+M8 暂停调节同步，par 6：橙在唯一路径上拿到暂停令牌，自动延迟一拍使双方同回合站上配对开关）。

## 组合顺序要点（集成测试覆盖）

- D2 先于 D1：传送离开脆弱格触发坍塌；传送落点占据离开者的脆弱格则不坍塌（ADR-016）。
- D2 后位置驱动 D3/D4/D5/D6：传送落点可压板、切映射、触发脉冲、拿令牌。
- 门状态读取回合开始状态（P4）：踩板/闩锁与穿门不可同回合；传送目标为关闭门当回合失败、下回合成功。
- 同格取消（P5）优先于一切动态结算：取消回合不坍塌、不闩锁、不计数。

## 阶段 09 输入（工具链约束）

1. 校验器须禁止：portal 不成对/同格入口重叠；多 `pulseSwitch` 配对数量 ≠ 2；`oneWay`/`portal` 压在出口上（出口永不锁定/自动离场）；多压板同 `doorId`（M1–M4 遗留）。
2. BFS 求解器直接复用 `applyCommand` + `stableHash`（已含 `pulseDoors`、`fragileCollapsed`、令牌、映射全部动态字段）。
