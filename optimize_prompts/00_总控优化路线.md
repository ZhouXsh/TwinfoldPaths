# 优化总控：UI、关卡差异化、地图扩展与创新玩法

## 目标
在不破坏《双生折线》既有核心规则、50 关可解性、离线单文件 H5 交付约束的前提下，完成四类改造：
1. 消除所有常见竖屏尺寸下的 UI 重叠、遮挡和信息层级混乱。
2. 降低连续关卡最短解方向序列和关键顿悟的重复度，让“地图不同但路线相同”的问题可量化、可回归。
3. 建立随章节递进的地图尺寸梯度，允许中后期使用更大棋盘，同时保证 320×568 小屏仍可操作。
4. 引入可配置的“探索迷雾”玩法：特定关卡只显示两名角色附近九宫格，已探索区域永久揭示；该机制只影响信息呈现，不改变领域层移动规则和可解性。

## 执行原则
- 所有工作在 `optimize/ui-level-variety-20260827` 分支完成，不直接污染 `main`。
- 先文档、后实现、再验收；每一阶段必须能单独回滚。
- 核心移动规则 R-01～R-07 与既有 M0～M8 不修改；探索迷雾定义为表现层规则 V1，而不是新的移动机关。
- 正式关卡仍必须通过 Schema、内容校验器和 BFS 求解器。
- 不以“肉眼看起来不同”作为关卡差异验收标准；新增解序列相似度审计。
- 不伪造 Playwright、构建、求解器执行结果；若当前连接器环境不能执行命令，在报告中明确标记“待本地/CI复跑”。

## 阶段拆分
- O1：UI 自适应布局与通关页重构。
- O2：关卡解序列相似度审计与重复关卡识别。
- O3：章节地图尺寸梯度与中后期大地图适配。
- O4：探索迷雾玩法（九宫格视野 + 已探索记忆）。
- O5：关卡内容重构、创新玩法投放与最终回归验收。

## 总体验收
- 320×568、360×640、390×844 三类竖屏中，首页、游戏 HUD、暂停/提示、通关页不存在文本或按钮互相覆盖。
- 通关页标题、星级、步数、按钮采用稳定的纵向流式布局，不再依赖易冲突的绝对坐标堆叠。
- 新增机器可读的关卡解序列相似度报告；连续普通关卡不允许出现完全相同最短解序列，教学关需显式豁免。
- 第 3～5 章至少出现 7×7、8×8 或更大的棋盘，渲染按可用区域自动缩放。
- 至少 4 个正式关卡启用探索迷雾，并至少覆盖“教学 → 组合 → 高难”三种使用方式。
- 50 关仍全部可校验、可求解、可自动回放通关。
