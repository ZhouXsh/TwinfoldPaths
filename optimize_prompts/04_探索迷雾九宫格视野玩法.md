# O4：探索迷雾（九宫格视野）玩法

## 设计定位
探索迷雾是“信息限制型”创新玩法，不改变移动、碰撞、机关、胜利条件，因此不侵入领域移动引擎。其价值在于把原本完全可见的静态规划，转化为“移动即侦察”的局部信息决策。

## 规则 V1
1. Schema v1 的正式关卡通过标签 `V1-fog` 启用探索迷雾。这样无需改动既有严格 JSON Schema 和 50 关解析协议，也不会影响求解器输入语义。
2. 默认半径为 1：以蓝、橙两名角色当前格为中心，各显示 3×3 九宫格，可见区域取并集。
3. 已经被任意角色看见过的格子永久记为 explored；explored 区域以低亮度显示，当前视野正常显示，未探索区域用雾层遮挡。
4. 角色自身、当前可见的墙/出口/机关正常显示；未探索区域不提前泄露内容。
5. 重开时 explored 重置；撤销时 explored 不回退，避免玩家通过撤销反复“抹除知识”，并减少状态复杂度。
6. 迷雾只存在于表现层，不写入 `GameState`，因此不会改变 BFS 的可解性、最短解与机关规则。

## 数据结构与兼容策略
`LevelDef` 预留了可选的表现层类型：
```ts
visibility?: { mode: 'full' | 'fog'; radius?: number };
```
但本轮 **Schema v1 的 JSON 不直接写 `visibility`**，正式内容统一使用 `V1-fog` 标签激活。原因是现有 `parseLevel` 与 `level.schema.json` 都采用严格未知字段拒绝策略；贸然给 50 关协议增加顶层字段会扩大兼容面。

后续如果升级 Schema v2，可把 `visibility` 正式纳入 Schema/解析器，并让标签方案平滑迁移。在此之前，`GameScene` 同时识别预留字段与 `V1-fog` 标签，保持扩展接口。

## 表现层实现
- `GameScene` 维护 `Set<string>` exploredCells。
- 每回合结算后根据两名角色位置更新 exploredCells。
- 在棋盘实体层之上绘制 fog overlay；当前可见格透明、已探索格半透明、未知格高不透明。
- 重开清空 explored；撤销仅恢复逻辑状态，不删除已经获得的地图知识。
- 使用纯 TS 的 `computeVisibleCells` 计算可见区域，便于单元测试。

## 本轮投放
- `level-031`：首次教学，配合单向格，让玩家理解“移动即探索”。
- `level-037`：与传送门组合，利用瞬间位置变化快速揭示远端区域。
- `level-040`：9×7 大型迷雾综合关，加入探索支路并组合传送、单向格、压板门。
- `level-047`：9×8 后期迷雾综合关，与暂停令牌、同步脉冲组合。

## 验收门
- 无 `V1-fog` 标签的关卡与旧版表现一致。
- fog 关开局只显示两名角色周围九宫格并集。
- 移动后新区域正确揭示，旧区域保持 explored。
- 重开清空探索记忆；撤销不清空已探索区域。
- 迷雾不修改领域 `GameState`，因此不能改变求解器结果。
- 至少完成 4 个正式 fog 关，覆盖“教学 → 传送组合 → 大地图综合 → 终章高级组合”。
