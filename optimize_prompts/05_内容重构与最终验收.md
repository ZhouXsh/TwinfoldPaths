# O5：内容重构、创新玩法投放与最终验收

## 目标
在 O1～O4 的基础能力完成后，对 50 关进行第二轮内容设计，使地图规模、解法节奏、机制组合和探索玩法形成可感知的章节递进。

## 执行任务
1. 运行路线相似度审计，按风险从高到低列出待改关卡。
2. 优先重构连续重复簇；每次改动 3～5 关后立即运行校验/求解，避免一次性大改导致难以定位回归。
3. 第 3～5 章引入大地图；每个大地图必须解释为何需要更大空间，例如多阶段同步、分离探索、机关顺序、传送回环，而不是单纯增加步数。
4. 至少 4 关启用 fog：1 个教学、1 个纯探索、1 个与传送/单向组合、1 个终章综合关。
5. 对 `parMoves` 重新求解并同步；一级提示只提示思路，不直接给完整方向序列。
6. 更新 manifest、难度报告、solution-variety-report 与优化总结。

## 最终强制验证
- `npm run format:check`
- `npm run lint`
- `npm run typecheck`
- `npm test`
- `npm run validate:levels`
- `npm run solve:levels`
- `npm run test:e2e`
- `npm run build`
- `npm run verify:dist`

## 最终验收门
- 50/50 Schema 通过、50/50 可解、50/50 自动回放胜利。
- 连续普通关无完全相同最短解；高相似簇均有设计解释或完成整改。
- 中后期地图尺寸明显提升，同时 320×568 无裁切。
- fog 关卡可玩、可理解，且不修改核心移动逻辑。
- 用户截图所示通关页重叠问题无法在三类目标视口复现。
- 新增机制与地图扩展没有破坏单文件离线交付。

## 交付
完成后创建 PR 合并到 `main`，PR 描述必须包含：改动摘要、关卡重构列表、迷雾关列表、尺寸分布、解序列相似度结果、实际测试结果、未验证项。
