# O1：UI 自适应布局与重叠清零

## 问题定位
用户截图中的通关页存在明显的纵向元素碰撞：主标题、副标题、步数统计、星级提示和操作按钮集中在同一小区域。现有 Phaser 场景普遍使用固定像素坐标，容易在 320×568 等短屏以及字体实际高度变化时重叠。

## 改造任务
1. 在 `src/scenes/dom-ui.ts` 增加统一的安全区/布局辅助函数，提供顶部、内容区、底部操作区的可用矩形。
2. 重构 `ResultScene.ts`：使用基于视口高度的纵向槽位，主标题、结果信息、星级、按钮分别占独立区域；按钮组固定在底部安全区，不与结果信息共享 Y 坐标。
3. 检查 `HomeScene.ts`、`ChapterSelectScene.ts`、`LevelSelectScene.ts`、`SettingsScene.ts` 与 `GameScene.ts` HUD，消除固定坐标造成的窄屏碰撞。
4. `GameScene` 棋盘区域必须根据 HUD 与底部控制区计算剩余高度，棋盘只在该区域内缩放居中。
5. 增加 E2E 布局断言：核心元素 bounding boxes 不相交，并覆盖 320×568 与 390×844。

## 验收门
- 通关页任意两段核心文本 bounding box 不相交。
- 按钮组与文本区至少保留 12px 视觉间距。
- 320px 宽度下按钮可点击区域不小于 40×40 CSS px。
- 旋转/resize 后重新布局，不产生旧位置残留。
